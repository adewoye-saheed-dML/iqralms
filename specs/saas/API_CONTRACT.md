# API Contract

## Authentication
- **Login**: `POST /api/auth/login/` - Accepts credentials, returns a REST Token.
- **Logout**: `POST /api/auth/logout/` - Deletes the Token assigned to the current user.
- **Tokens**: Long-lived Token Authentication is used (Django REST Framework `TokenAuthentication`). There is no refresh token behavior.
- **Sessions**: Used in development and by admin (`SessionAuthentication`).
- **401 Behavior**: Unauthenticated requests return a 401 status code with a standard DRF detail message.
- **CSRF**: Enforced for session-authenticated requests, not for token-authenticated requests.

## Tenancy
- **Authority Chain**: User -> Organization Membership -> Organization Route -> Role Permission -> Tenant Queryset.
- **Isolation**: Tenant isolation is strictly enforced. Cross-tenant IDs will not bypass isolation; they return 404. Non-members and suspended members are denied access (403 or 404).

## Roles
- **Available Roles**: OWNER, ADMIN, STAFF, TEACHER, STUDENT, PARENT.
- **Permissions**: Sensitive endpoints explicitly check these roles using custom permission classes (`IsOrganizationAdmin`, `IsTeacher`, etc.).

## Errors
- **400 Validation Error**: Field-specific validation errors from serializers.
- **401 Unauthenticated**: Invalid or missing token/session.
- **403 Forbidden**: Valid authentication, but insufficient role or suspended membership.
- **404 Not Found**: Resource does not exist or belongs to another tenant.
- **409 Conflict**: Returned when an operation cannot be completed due to conflicting state (e.g., overlapping bookings).
- **429 Throttled**: API rate limits exceeded.

## Pagination and Filtering
- **Pagination**: Standard limit/offset or page number pagination (e.g., `page`, `page_size`). Default and max limits apply based on DRF settings.
- **Filtering**: Filters are applied after tenant scoping. Only explicitly defined filter fields are exposed.

## Date/Time
- All timestamps are timezone-aware ISO 8601 values (typically UTC).

## Enums
- Machine values for roles, statuses, and types are stable and should be used as API identifiers.

## Uploads and Bulk Import
- **Uploads**: Use private storage. Public media routes are not exposed. Signed URLs are used for temporary access (e.g., audio samples).
- **Bulk Import**: Follows `upload -> validate -> commit -> result` flow. All-or-nothing transactional behavior.

## Audit API
- **Domain**: `audit_logs/`
- **Scope**: Organization-scoped (`/api/organizations/<org_id>/audit-logs/`).
- **Mutability**: Audit logs are read-only (immutable). No PATCH/PUT/DELETE.
- **Request ID**: `X-Request-ID` is supported for tracing and correlation.

## Request Correlation
- `X-Request-ID` is accepted in request headers. If absent, it is generated by the server. It is returned in response headers and logged in audit trails. It is not an authentication credential.

## Retry and Concurrency
- Concurrency protections (locks/transactions) are implemented in the backend (e.g., for scheduling). Clients should handle 409 conflicts and may retry idempotent operations.
